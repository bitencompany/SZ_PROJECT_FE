# 이름결 — 사주·성명학 웹 서비스

Next.js App Router / TypeScript / Tailwind 기반입니다. 현재 사용자 흐름은 **비회원 이름·한자·출생 정보 입력 → 무료 미리보기 → 더 자세한 내용 보기 → 카카오 로그인 → 입력 확인·보관**입니다. 결제는 비활성이며, 상세 분석·내 풀이함 조회 UI는 후속 연동에 맞춰 준비되어 있습니다.

## 실행

```sh
npm install
# .env.local이 없는 새 환경에서만 실행합니다.
test -f .env.local || cp .env.example .env.local
npm run dev
```

기본 접속 주소는 http://127.0.0.1:3000 입니다. 다른 포트를 쓰면 APP_URL도 일치시켜 주세요. 키 없이 무료 이름 분석과 미설정 안내를 확인할 수 있습니다. `예시로 채우기`는 김서준(金書俊)을 선택합니다.

## 현재 구현

- 한글 이름 → `/api/hanja` → 한자 선택 → `/api/name` → 원형이정·81수리·발음오행 미리보기.
- 출생 정보를 입력하고 동의하면 이름 분석에 이어 `/api/sazu`에서 사주를 요청합니다. 이름 분석 성공 후 사주만 실패해도 이름 미리보기는 유지합니다.
- `/api/sazu`는 FE 서버에서 BE로 요청하고 응답을 변환합니다. SAZU_API_KEY는 BE에만 설정합니다. FE에서 공급자를 직접 호출하지 않습니다.
- 카카오 로그인은 Supabase Auth의 PKCE와 서버 쿠키로 처리합니다. 인증 설정이 없으면 준비 중 안내를 표시합니다.
- 상세 보기 클릭 시 입력을 같은 탭의 sessionStorage에 최대 30분 임시 보관하고, 로그인 뒤 `/checkout`에서 확인·저장합니다. 외부 제공 동의는 자동 복원하지 않습니다. 서버 저장 성공 시 임시 보관을 삭제합니다.
- 로그인·저장 동의 후 BE 요청 보관 API를 사용합니다. 최근 입력은 이 브라우저에서 저장한 최대 10건을 표시하며 개별 조회·삭제를 지원합니다. 계정 전체 입력 목록 API는 BE 추가 요청 상태입니다.
- 결과 목록/상세, 주문 상태, paid+queued/processing 제한 폴링, 생성 실패 재시도는 BE에 연결했습니다. BE AI 구현은 전달받았으나 실키 검증은 남아 있습니다. **PG 계약 전이므로 결제는 비활성입니다.**

## 연결 설정

- 최신 로컬 설정·원격 DB 적용·남은 실계정 검증: [BACKEND_SUPABASE_STATUS_20261104.md](./BACKEND_SUPABASE_STATUS_20261104.md).
- 신규 로그인 설정: [AUTH_SETUP.md](./AUTH_SETUP.md).
- 수신한 최신 BE 계약: [BACKEND_API_20261030.md](./BACKEND_API_20261030.md).
- BE 운영·전체 DB 마이그레이션: [BACKEND_OPERATIONS_SETUP_20261030.md](./BACKEND_OPERATIONS_SETUP_20261030.md).
- FE 반영 결과와 새 이름 형식 확장 요청: [FRONTEND_INTEGRATION_20261030.md](./FRONTEND_INTEGRATION_20261030.md).

`.env.example`의 `BACKEND_API_URL`은 개발용 `http://127.0.0.1:3017`이며 운영은 HTTPS가 필요합니다. FE/BE에 동일한 `BFF_SHARED_SECRET`(최소 32바이트)을 설정합니다. 실제 검수 한자 데이터가 없으므로 `BACKEND_NAME_ENABLED=false`로 유지합니다. true 상태에서 연결 오류를 예시 데이터로 대체하지 않습니다.

사주 BFF는 새 `/api/sazu/preview` 계약을 사용합니다. 기본 `PREVIEW_IP_SOURCE=disabled`이며 신뢰 IP가 없으면 외부 호출을 차단합니다. 직접 Vercel 배포에서만 `vercel`로 설정합니다. 로컬/다른 호스팅은 신뢰 IP 어댑터가 준비되기 전에는 사용할 수 없습니다. 세부 설정은 FE 반영 문서를 참고하세요.

## 데이터 기준과 제한

- 성과 이름을 따로 입력합니다(성 1~2글자, 총 한글 2~20글자). 한자 선택칸마다 ‘한자가 아니에요’ 체크박스가 있어 성만 한자이거나 일부 글자만 한자인 이름도 표현할 수 있습니다. 한자 없는 글자의 위치를 보존하고, 혼합 이름은 발음오행·사주를 제공하며 전체 획수 수리를 계산하지 않습니다.
- 기존 성 1자+이름 2자 한자 이름만 수리 계산·계정 보관을 지원합니다. 다른 형식은 한자/발음오행/사주 무료 미리보기를 제공하고 수리·계정 보관·상세 분석은 BE 확장 대기입니다.
- 양력·국내 출생을 지원합니다. 시각 미상은 BE에 hour=null, minute=0으로 보냅니다.
- SAZU `data.sandbox=true`는 고정 샘플로 표시합니다. 미제공 모듈은 오행 0개 등으로 추정하지 않습니다.
- `src/data/hanja.ts`는 **미검수 예시 목록**이며 전체 인명용 한자 DB가 아닙니다. 서비스 출시용으로 사용하지 않습니다.
- 원획과 사전 총획을 구분합니다. 泰는 국내 작명 자료의 원획 기준 9와 사전 총획 10을 표시하며 대조 출처를 제공합니다. 기존 예시값의 최초 출처는 미기록이며, 이 한 글자의 대조가 전체 카탈로그 검수 완료를 뜻하지 않습니다.
- `src/data/suri_81.json`은 제공된 `81.md`를 옮긴 자료입니다. 81 초과 시 80을 반복 차감합니다. 된소리·자원오행·불용문자 중 근거 없는 값은 미분류/null로 유지합니다. 오행 개수만으로 용신을 판단하지 않습니다.
- Supabase·Kakao 로컬 설정과 원격 DB 적용은 완료했습니다. 실제 계정 로그인·입력 저장 E2E와 SAZU/PG/LLM 실호출 검증은 남아 있습니다. 외부 서비스 성공을 가정한 결제나 가짜 상세 결과를 만들지 않습니다.

## 검증

```sh
npm test
npm run typecheck
npm run build
```

테스트는 계산 경계·입력 검증·BE 계약·OAuth 복귀 경로·임시 입력 만료·PostgreSQL RLS를 확인합니다. PGlite 테스트는 Supabase 역할을 로컬에서 재현하며 원격 DB 적용 또는 실제 OAuth·결제 검증을 대신하지 않습니다.

FE(3000)와 BE(3017)를 실행한 뒤 `npm run test:local`로 비회원 보호 화면, OAuth 시작·취소, BFF 공유 비밀 및 카탈로그 준비 중 응답을 검사할 수 있습니다. 현재 비활성 설정을 전제로 하며 실계정 로그인·저장·결제를 실행하지 않습니다.
